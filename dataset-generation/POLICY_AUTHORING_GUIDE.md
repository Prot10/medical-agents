# NeuroBench clinical-policy authoring guide

NeuroBench v2 evaluates what an agent does, what evidence it discovers, when it stops and what assessment it submits. It does not prescribe or store a hidden reasoning trace.

## Authoring unit

Each case is a complete simulated patient with schema version `2.0`. Generation must set `ground_truth.review_status` to `draft`. Only the physician-review workflow can promote a policy to `approved`.

A policy contains:

- an accepted diagnosis set and optional ICD codes;
- a differential with case-specific distinguishing features;
- action criteria representing evidence goals;
- avoided-action criteria for waste, harm and contraindications;
- clinically justified sequence constraints;
- a stop rule;
- required and prohibited assessment recommendations;
- observable key clinical evidence and explicit red herrings.

## Action criteria

An action criterion describes a clinical goal, not a fixed step number. Its `alternatives` are interchangeable tool-call patterns that satisfy the same goal. Add every clinically equivalent path you intend to score as correct.

Each criterion needs:

- a stable unique lowercase `criterion_id`;
- a concise label;
- `required`, `recommended` or `optional` importance;
- at least one `tool_name` plus the minimum `required_arguments`;
- expected observable evidence;
- a clinical rationale and citations.

Use only arguments needed to identify the action. Over-specific patterns can reject clinically equivalent calls.

## Avoided actions

Use `waste` for unnecessary resource use, `harm` for actions with a material adverse-risk signal and `contraindicated` when the action should not be performed in this case. Match the actual tool call and explain the case-specific reason. General preference is not a contraindication.

Repeated calls are scored separately by the harness and need not be encoded as invented positive criteria.

## Sequence and stopping

Sequence constraints may reference only existing action-criterion IDs. Use a hard constraint only when reversing the order creates a safety problem; otherwise use soft. Never add a synthetic criterion to repair a dangling reference.

The stop rule lists the required criteria needed before assessment and the maximum reasonable additional actions after that point. It should reward adequate, efficient workups without demanding one exact trajectory.

## Assessment policy

Required recommendations are clinical actions that should appear in the final assessment. Prohibited recommendations capture unsafe or inappropriate management. Keep them case-specific and directly reviewable.

## No gold chain-of-thought

Do not author private reasoning, `<think>` text, ReAct transcripts or a canonical trajectory. Training episodes are generated by executing agents against the environment, replay-validated and labeled `candidate_not_gold`. Their actions may be useful supervision after quality gates, but their reasoning is not physician ground truth.

## Physician approval gate

A case is approved only when two independent physicians approve all seven review dimensions:

1. presentation coherence;
2. tool-output fidelity;
3. diagnosis and differential;
4. action-policy coverage;
5. avoided-action safety;
6. sequence and stopping;
7. assessment recommendations.

A third physician adjudicates disagreement. Any unresolved error blocks approval. Reviewer specialty and credentials should be recorded when available.
